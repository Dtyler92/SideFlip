# Document job protocol v1 — local, default-off seam

## Status and activation boundary

`processLeasedJob` dispatches an explicitly server-marked `execution_lane: 'document_v2'` lease to `processDocumentLeasedJob`. It requires strict `config.documentLaneEnabled === true` **and** every injected capability/adapter. Missing configuration or adapters throws `DOCUMENT_LANE_DISABLED`, without calling the legacy provider or retry-capable failure RPC.

This is not a public endpoint, authentication mechanism, deployed SQL implementation, or new queue. The shipped `index.ts` does not supply this flag, marker or adapters. No public/environment flag enables it. Existing unmarked jobs retain their existing discovery/normalization/retry behavior. The additive local SQL implementation below now supplies the transaction adapter, but production activation still requires separately approved acquisition/provider/dispatch integration.

## Binding and trusted methods

The lease binds the existing job, owner, item, confirmed fingerprint, original request snapshot, initial execution revision, policy, lease token and original reservation month/amount. Exactly the first attempt is accepted. Treat the execution revision as a sealed origin value, not a mutable completion revision. Do not derive authority from browser JSON or the `capabilities` object: capabilities describe an already trusted implementation, not proof of its behavior.

`jobs.read(binding)` returns exactly that binding and a state of `ready`, `attempted`, `completed`, or `failed`. It must independently derive ownership/authorization, current identity confirmation, policy and entitlement, durable reservation, cancellation and lease validity from authoritative database state. The originating job must be the existing explicitly/manual-enqueued job; this seam never creates another. Completed read-only replay still requires current authorization/identity/policy/entitlement and no cancellation, but does not require an unexpired execution lease. A real read/status RPC must authenticate the requester and recover the stored binding; never expose a lease token to native/web clients.

`jobs.claim({binding, source})` must atomically compare-and-set the existing ready job, recheck every fence and reservation, store the exact independently derived source hash/pages and one unique attempt ID, and durably consume the sole extraction attempt **before** returning `{claimed:true, attemptId}`. Concurrent or replaying workers lose that CAS. A claim without acknowledgement is not permission to extract. The core rereads the persisted attempt before invocation. Expiry/reaper/queue redelivery must never turn an attempted document job back into ready or feed it into the legacy retry branch.

`jobs.commit({binding, attemptId, record, costInUsdTicks})` must in **one database transaction** recheck ownership/current fingerprint/entitlement/policy/cancellation/lease/reservation, immutable-append the v2 template, link its ID and exact record/source/cost to the originating job, and settle reservation/accounting. Return no approved legacy proposal or recurring schedule. A stale/cancelled job must not append. Idempotent reconciliation must return the same committed record, never a new version. The local implementation is `finalize_document_job_v1` in `20260918120000_atomic_document_research_jobs.sql`; it remains unapplied outside disposable tests.

`jobs.fail({binding, attemptId, costInUsdTicks, code, requeue:false})` must be terminal and idempotent; completed state cannot regress. Preserve exact safe nonnegative ticks when available. `null` means the provider may have charged: hold/charge the reserved worst case pending explicit reconciliation, never treat it as zero or release the entire reservation. Always use the original reservation month. Over-budget known cost must remain recorded as actual, not silently capped. A lost failure response or worker death leaves the attempt consumed. Do not invoke released `fail_my_stuff_research_worker_v2` for this lane. Its existing retry behavior is intentionally unchanged.

## Source and extraction boundaries

`acquireDocument({binding})` is required, trusted, and non-billable in this seam. It must return an original-byte-derived bundle accepted by the existing private reader/WeakSet gate; serialized JSON, guessed hashes and model-asserted source flags are rejected. It must not run a hidden paid discovery pipeline. Concurrent deliveries can read the source more than once before CAS; only extraction is single-attempt. Failed/missing acquisition throws `DOCUMENT_SOURCE_UNAVAILABLE` before claim/extraction; the core now invokes the separate ready-only capability when the trusted RPC adapter supplies it. The trusted `jobs.failPreflight({binding, attemptId})` capability now maps to `fail_document_preflight_v1`: under the same job/execution locks it may settle zero only while ready with no source. It returns false without writes if claim or completion won. Identical ready-failure replay returns true once accounting is already settled. The local dispatcher and explicit bounded recovery below now use this capability.

Current original-byte reader uses local Node/Python PDF parsing. Production authenticated acquisition, durable byte storage, page selection, Edge-compatible parser/reader and reviewed source policy are **not implemented** here. No hard-coded Ford automatic retrieval exists. The fixture's hash binding is not publisher authentication or vehicle applicability.

`extract({request})` receives only the document request, not job/owner/item IDs, VIN, lease token or reservation. It must implement a bounded request deadline/abort and response size, provider/model/privacy policy and **no retry**. It returns `{extraction, usage:{costInUsdTicks}}`; a failure may carry valid `costInUsdTicks`. The seam does not itself time out a hung arbitrary injected function; bounded transport and lease-deadline integration remain adapter obligations. Tests inject retained genuine output and timeout errors without any provider calls. The existing live document adapter accepts a bundle, not this request signature: it is not silently wired or claimed as integrated.

The core validates extraction against the independently read source, prepares the existing schema-v2 ingestion envelope, and binds source/job metadata. It preserves `needs_review`, false semantic/source-authentication/applicability/apply gates, conditions, evidence, unresolved passages and coverage. Lease tokens are excluded from owner-readable records. The original request snapshot remains owner-private job metadata and is never sent to the extractor. A future production adapter should minimize it further according to its authenticated lease contract.

## Readback and failure recovery

Success requires a completed persisted job snapshot AND `storage.read(ownerId, templateId)` with exact ID, owner and canonical JSON record equality. Replay reads that same record without source acquisition, provider invocation or append. An uncertain commit response is reported as unconfirmed; a subsequent read-only replay may recover an already completed result. Never re-extract or append another version to repair a missing acknowledgement.

`tests/helpers/document-job-harness.js` implements the **in-memory contract double**, not database authentication, atomicity or spend accounting. `tests/sql/document-job-local.mjs` combines this double with actual service-role immutable SQL append and authenticated owner readback. It deliberately demonstrates that an append followed by a lost acknowledgement can leave an orphan when the job double and SQL are not transactional. That test proves no automatic repeated extraction/append and honest failure, **not** an atomic job+template integration. Production must eliminate that gap through the transactional RPC, not by hiding it with retries.

## Additive local SQL implementation (unreleased)

`document-job-rpc.js` maps the trusted injected Supabase-style client to `read_document_job_v1`, `claim_document_job_v1`, `finalize_document_job_v1`, and `fail_document_job_v1`. It has no credentials, provider, transport, source acquisition or activation defaults. The core now accepts the existing database's literal text policy version as well as the historical numeric test-double version; it never substitutes a guessed number for a database policy token.

`prepare_document_job_v1(job_id, lease_token)` adopts only an existing running first lease with a persisted reservation, existing attempt, no prior spend/settlement/release, and current fences. It returns the sealed binding. The orchestrator must use that binding's fields for the marked lease, retaining attempt_count=1; no second job, attempt or reservation is created. Repeated preparation returns the same binding. Adoption moves the existing job to `document_pending` and removes the old queue delivery transactionally. Released legacy lease/reaper/failure functions ignore these non-running/non-queued jobs. A completed result uses `document_complete`, failure `document_failed`, and never masquerades as approved/applied legacy research.

The new `private.my_stuff_document_executions` is a job-keyed extension, not a replacement queue/accounting system. It stores the sealed binding/source, original attempt ID, terminal usage and exact original template link. SQL locks serialize claim and finalize; immutable storage validation, link, usage, settlement and unused-reserve release share one transaction. A deferred constraint trigger also prevents direct document-family storage calls from committing an unlinked original. Explicit later correction versions may append, but cannot retarget the job result or overwrite the raw version.

Service direct DML on the existing jobs/attempts/budget ledger is revoked: the released SECURITY DEFINER worker RPCs continue operating, and the local legacy retry regression proves this. The new execution table has no browser/service table grants. Only trusted service RPCs write; the authenticated owner result API derives ownership with `auth.uid()` and excludes the lease token.

Unknown cost keeps full original-month reserve consumption and null exact ticks; known overrun stores uncapped actual ticks/cents and an additional consumed-reservation ledger entry so the existing reservation-minus-release budget calculation includes the overrun. Existing ledger entries are never reset. The additive correction `20260918130000_fix_document_preflight_and_active_owner.sql` separates nonbillable preflight into `fail_document_preflight_v1`. The original `fail_document_job_v1(..., 0, 'DOCUMENT_SOURCE_UNAVAILABLE')` signature delegates to that ready-only capability so stale old callers cannot zero-settle a claimed attempt. Other failure codes require an attempted execution; legitimate post-claim known-zero failures remain supported there, while unknown ticks retain the full reservation. Acquisition failure cannot be reported through that attempt-owned path. The core now invokes preflight settlement; the new local migration below supplies explicit recovery and reconciliation RPCs, but no scheduler or external usage lookup is enabled.

The same additive correction transactionally replaces `my_stuff_research_one_active_user_uq`, retaining queued/running/awaiting_review/approved and adding `document_pending`; document_complete/document_failed remain terminal and release the active slot. Existing duplicate active owners would fail migration rather than silently cancel work. Actual authenticated enqueue replay retains its original job ID; a new mutation for either the same or another item is rejected while a document job is ready/attempted. Rate and budget checks remain independent and can reject earlier. Global legacy running/provider-dispatch selectors are unchanged; this correction does not claim a production global document-dispatch fence.

`tests/sql/run-document-job-atomic-local.sh` is the real transaction acceptance runner. It uses independent PostgreSQL connections, six-way worker delivery, concurrent duplicate finalization, observed identity-lock contention, connection closure before commit, discarded acknowledgement after commit, and test-only failure triggers after every finalize write boundary. The older `run-document-job-local.sh` deliberately retains its historical non-atomic negative demonstration; it is not the atomic acceptance runner.

Production gates remain: catalog/grant review and migration approval; safe lane dispatch before any legacy provider invocation; real enqueue/lease/status/cancel integration; durable original acquisition; bounded live provider transport; owner semantic review/application and PWA/native handoff. The original 26 acceptance groups use explicitly seeded first-lease/reservation rows. The added correction harness also exercises fresh-owner actual authenticated enqueue → service lease → adoption, both claim/preflight and adoption/enqueue lock orders, cancellation races, and retained offline extraction with known/unknown cost. All use local pgmq/cron/net stubs, not real provider calls or deployed queue integration. The correction runner writes isolated evidence under `retained-ford-quality-pass/review-corrections/`.

## Local enqueue/dispatch/cancellation checkpoint

`20260918140000_document_dispatch_local.sql` and `document-dispatch.js` join actual authenticated enqueue to first-lease adoption, SQL claim, injected extraction, atomic finalization and exact owner status. The flag stays default OFF. `enqueue_my_document_job_v1` reuses all existing enqueue checks/reservation and marks `document_queued` in the same transaction, removing its legacy queue message. The old worker cannot consume it. `lease_document_dispatch_v1` never creates a second reservation or retries a claimed document. Pending READY acquisition does not occupy paid authority; document claim and legacy running admission share the global advisory lock, with a trigger also fencing older lease entrypoints.

Cancellation releases queued/READY work without paid cost; claimed cancellation retains the owner slot and global paid fence until terminal accounting. `recover_document_dispatch_v1(limit)` explicitly settles at most 25 expired executions after a five-minute post-lease grace: READY zero, attempted unknown/full reserve. It never requeues. Real transport termination/deadline proof and scheduling are still activation gates. `reconcile_document_usage_v1` requires a trusted known cost for the exact original unknown attempt, appends an idempotent correction and original-period unused-balance release, and does not re-extract, create a reservation, mutate the original unknown settlement, or publish a template. Above-reservation reconciliation is rejected for separate accounting review. No automatic provider usage lookup exists.

The owner result RPC now covers pre-adoption states, cancellation/accounting pending, known/unknown/reconciled usage, and the exact original immutable template link. No lease or provider body is returned. Source acquisition and live extraction remain explicit injected boundaries; `index.ts` is intentionally not activated. SQL tests exercise the real bounded document HTTP adapter with mocked fetch and retained source/output, not a paid call.

Run `DOCUMENT_DISPATCH_TEST=1 bash tests/sql/run-document-job-atomic-local.sh`. This first runs the original/correction SQL stages, then applies the new migration only to the disposable database and runs `document-dispatch-local.mjs`. ## Transport quarantine correction — supersedes timeout policy above

`20260918150000_document_transport_quarantine.sql` is additive/local/unapplied. The current RPC adapter requires this final migration stack and uses `fail_document_job_v2`, `observe_document_transport_v1`, and `get_document_transport_status_v1`. Historical stage-only runners above do not include this contract; use the final-stack runner in `retained-ford-quality-pass/timeout-fence/run-final-schema.sh`.

The actual dispatcher durably acknowledges `start` before invoking once, passes `extract({request, signal})`, and bounds the extraction wait to at most 240000 ms (default); it polls cancellation/expiry/terminal recovery every 1000 ms by default. Lost start ACK means zero invocation. Abort is requested, not asserted effective: even a locally rejected promise/socket does not establish remote compute termination. `in_flight`, `abort_requested_remote_unknown`, and `local_stopped_remote_unknown` retain global admission across both lanes regardless of terminal accounting or elapsed SQL lease. Deletion/cascade cannot erase an uncertain fence.

Promise fulfillment and plain `remoteCompletionConfirmed` properties confer **no terminal authority**. The xAI adapter alone mints process-local, one-use WeakMap evidence tied to the exact extraction request and invocation AbortSignal. Forward `extract({request,signal})` to `provider.extract(bundle,{signal})` and return its original result/error object. Copies, flags, queued values, different requests/signals and replay fail closed. HTTP must be 200, the parsed envelope must match the exact requested model, object `response`, nonempty string response ID, completed status and complete assistant text output, with no refusal/error/incomplete details. Safe exact usage and JSON output parsing must succeed. No model aliases or guessed response-ID prefix are accepted. Document-content validation remains separate: a valid terminal provider response may still fail schema-v2 ingestion or local settlement. The evidence can accompany a local settlement error. Known usage on invalid responses is retained independently and cannot release quarantine.

The transport deadline now includes start and completion acknowledgement; it is not disabled when the extractor settles. Timeout aborts the provider and acknowledgement request, rejects the foreground operation, and never resumes template ingestion on late acknowledgement. The RPC adapter separately bounds each call (default 10000 ms; dispatcher uses `transportOptions.rpcTimeoutMs`, otherwise explicit transport timeout, otherwise 10000 ms), invoking PostgREST's `abortSignal` where available. Failure settlement has its own bounded cleanup window. A timeout with `settlementUnconfirmed:true` leaves the durable consumed attempt/reservation/fence for explicit recovery. Aborting a client request does **not** prove SQL cancellation; late server commits remain possible and must be read back/reconciled idempotently. Acquisition, initial dispatch lease and external storage hooks are not covered by an overall worker deadline. Production database statement/lock deadlines and teardown/reconciliation orchestration remain activation gates.

Late trusted responses only update lifecycle/accounting, never append a template. Late untrusted responses may retain measured usage but leave quarantine intact. Accounting reconciliation alone never releases an uncertain transport. Retained Responses contract source: `document-maintenance-pipeline/ford-live-document-trial/official-doc-2.md`, response body lines 106–158. This is the retained documented contract, not a newly verified live provider guarantee.

Owner status exposes `transportState`, `admissionQuarantined`, and `reconciliationRequired`. No expiry clears ambiguity. Only a separately approved operator decision may deliberately call service-only `authorize_document_transport_release_v1` with an authorization UUID and explicit acceptance of remote-unknown risk, after terminal accounting. Approval must be independent of the timed-out worker and retained with approver, rationale and evidence in an external audit record; the current SQL UUID alone does not prove independent approval or preserve an immutable authorization history. This is a risk override, NOT proof that remote work stopped; the dispatcher never invokes it. Unknown cost can remain reserved after release. Provider bill lookup, operator approval UI/audit workflow, production factory and remote lifetime guarantees remain activation gates. A process crash may require explicit reconciliation; no background callback is guaranteed to survive worker teardown.
